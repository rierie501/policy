Audio Recorder and Editor: foreground-service demonstrations

Recorded 16 October 2026 using the restoration source in an isolated Android 16 QA installation. Production package: rierie.media.audiorecorder. QA package: rierie.media.audiorecorder.permissiontest. The QA build uses the same recording, playback and processing implementation. These videos demonstrate the planned replacement, not the old production build. No personal recordings or signed-in accounts were used. Emulator microphone audio is silent; editor inputs are synthetic tones.

Microphone: user-started background recording

The recording screen starts capture, Home backgrounds the app, the notification shows recording and pause/stop controls, then Stop & save creates the result. Delaying recording loses the beginning; interruption loses later audio.

Direct microphone video

Media playback: user-started audio preview

A synthetic local recording opens in the editor. Playback can be paused/resumed and continues outside the editor, with controls in the notification. Interruption stops listening.

Direct playback video

Media processing and data sync: local audio transformation

The user chooses Echo and Save copy. A separate result is processed while the app is backgrounded, with a progress notification, then appears in Recordings. Interruption can leave an incomplete result and require retry; the input is preserved.

Android 15 and newer use the mediaProcessing foreground-service type. Android 10–14 use dataSync for this same local transformation because mediaProcessing is unavailable. This video is on Android 16; it demonstrates the shared workflow, not an Android 14 runtime. No network synchronization is performed by this operation.
